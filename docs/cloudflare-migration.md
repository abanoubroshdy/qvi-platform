# Cloudflare Workers migration (phase 1)

getqvi.com stays on Vercel. This repository can also build the same Next.js app as a Cloudflare Worker with OpenNext. Nothing in this phase deploys the Worker, attaches a domain, edits DNS, or deletes the Vercel project.

Phase 1 is the hosting path for the site. Licensing APIs for the QV1 desktop app are not implemented here.

## Investigation

| Area | Finding |
| --- | --- |
| Next.js | `14.2.35`, App Router, `output` not set (default Node server). React 18. |
| Router | `app/`. No `pages/` routes. Middleware is `middleware.ts` (Edge, the Next.js 14 default). |
| Rendering | The root layout calls `headers()`, so HTML is dynamic SSR. No ISR, no `revalidatePath` / `revalidateTag`, no server actions. |
| API routes | `nodejs` runtime on `/api/contact`. `/api/geo`, `/api/supabase-config`, and `/qv1/download` are `force-dynamic`. |
| Images | The only `next/image` usages pass `unoptimized`. Config now sets `images.unoptimized` so Workers does not need a Cloudflare Images binding. |
| Vercel packages | No `@vercel/*` dependency and no `vercel.json`. `VERCEL_URL` and `VERCEL_PROJECT_PRODUCTION_URL` are only a site-URL fallback. |
| Geo | `/api/geo` used `x-vercel-ip-country`, then `cf-ipcountry`, then `x-country-code`. It now prefers Cloudflare `request.cf.country` and still accepts those headers, so Vercel behavior stays. |
| R2 downloads | `/qv1/download` presigns with `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` against `https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com`, bucket name `qv1-downloads`. The public installer parts redirect to `https://dl.getqvi.com/qv1/evaluation/:path*`. `downloads.getqvi.com` is the same R2 public surface, not this Worker. |
| Email | `/api/contact` calls `https://api.resend.com/emails`. |
| Auth | Supabase Auth via `@supabase/ssr`. The browser can load the URL and anon key from `/api/supabase-config` at runtime. |
| Ads | Google AdSense. Client and slot fall back to the ids in `lib/adsense.ts` when unset. |
| Audio tools | ffmpeg.wasm in the browser, core files from `unpkg.com`. No server ffmpeg. |
| Workers gaps | No D1, KV, or R2 **binding** is required for this app. Do not proxy the Setup exe through the Worker. |

`@opennextjs/cloudflare` **1.16.0 and later require Next.js 15 or 16**. This repo stays on 14.2.35 so the Vercel build does not take a framework upgrade. The Worker adapter is pinned to **1.15.1** (last release whose peer range includes `next@^14.2.35`) and Wrangler **4.59.2**.

## What runs on the Worker

- Worker name: `getqvi-web`
- Config: `wrangler.jsonc`
- OpenNext config: `open-next.config.ts` (default dummy cache; no revalidation)
- Compatibility date: `2025-12-01`
- Compatibility flags: `nodejs_compat`, `global_fetch_strictly_public`
- Static asset binding: `ASSETS` (generated by the OpenNext build)
- `workers_dev`: true, so a future deploy can be reached at `getqvi-web.<account>.workers.dev`
- No `routes`, no custom domains, no D1, no KV, no R2 binding, no Durable Objects, no Images binding

`nodejs_compat` is required by OpenNext and by the AWS SDK presigner. `global_fetch_strictly_public` is the adapter default: `fetch` can call public hosts (Supabase, Resend, R2) and cannot use it to reach a binding.

Scripts:

- `npm run build:worker` — copy pdf.js assets, then `opennextjs-cloudflare build`
- `npm run preview` — build and run the Worker locally
- `npm run deploy` — build and deploy (do not run this until the manual steps below)
- `npm run upload:worker` — build and `wrangler versions upload` (a version, not a traffic shift)
- `npm run cf-typegen` — generate `cloudflare-env.d.ts` (gitignored)

`npm run build`, `npm start`, and the Vercel project are unchanged.

Copy `.dev.vars.example` to `.dev.vars` for local preview. `.dev.vars` is gitignored. Do not put real secrets in git.

## Environment variable names

Set names only. Never commit values. On Cloudflare, runtime names are Worker secrets or plain vars (`wrangler secret put <NAME>`). `NEXT_PUBLIC_*` values are also inlined by Next at **build** time, so a beta build must see the beta site URL in the environment before `opennextjs-cloudflare build`.

Build-time (client bundle and metadata):

| Name | Notes |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://beta.getqvi.com` for the beta build, `https://getqvi.com` for production. If unset, the app falls back to `https://getqvi.com`. |
| `NEXT_PUBLIC_SUPABASE_URL` | Optional at build time. Alias: `SUPABASE_URL`. The known project URL is the code fallback. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Publishable/anon key. Aliases: `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_ANON_KEY`, `SUPABASE_PUBLISHABLE_KEY`. Runtime `/api/supabase-config` can supply it if it was not inlined. |
| `NEXT_PUBLIC_ADSENSE_CLIENT` | Optional. Blank disables the field. Unset uses the default in `lib/adsense.ts`. |
| `NEXT_PUBLIC_ADSENSE_SLOT` | Optional. Same rule. |
| `NEXT_PUBLIC_ADSENSE_SLOT_TOP` | Optional. |
| `NEXT_PUBLIC_ADSENSE_SLOT_BOTTOM` | Optional. |

Runtime only (Worker secrets; not `NEXT_PUBLIC_`):

| Name | Notes |
| --- | --- |
| `RESEND_API_KEY` | Contact form. |
| `CONTACT_FROM_EMAIL` | Example shape: `QVI Contact <noreply@getqvi.com>`. Domain must stay verified in Resend. |
| `CONTACT_TO_EMAIL` | Optional. Defaults to `support@getqvi.com`. |
| `R2_ACCOUNT_ID` | S3 endpoint host. |
| `R2_ACCESS_KEY_ID` | R2 API token id. |
| `R2_SECRET_ACCESS_KEY` | R2 API token secret. |
| `R2_BUCKET` | `qv1-downloads`. |
| `QV1_OBJECT_KEY` | Optional. Defaults to `qv1/evaluation/QV1-Setup-Evaluation.exe`. |

`SUPABASE_SECRET_KEY` is mentioned in `.env.example` and is **not read** by the current server code. Do not set a service-role key on the Worker until a route needs it. The anon key must not be a service-role key; the app rejects those.

Do not rely on `VERCEL_URL` or `VERCEL_PROJECT_PRODUCTION_URL` on Cloudflare. Set `NEXT_PUBLIC_SITE_URL` instead.

In Supabase → Authentication → URL Configuration, add the beta origin before testing sign-in:

- Site URL can stay `https://getqvi.com` until cutover
- Redirect URLs: `https://beta.getqvi.com/**` and `https://beta.getqvi.com/auth/callback`

Add `beta.getqvi.com` as a site in Google AdSense before expecting ads on the beta host.

## GitHub Actions

Workflow: `.github/workflows/cloudflare-worker.yml`.

- On every push and pull request: `npm ci`, `npm run build:worker`, and `wrangler deploy --dry-run`. No Cloudflare credentials. No deploy.
- `deploy-preview` runs only for a manual `workflow_dispatch`, and only when the repository variable `CLOUDFLARE_PREVIEW_DEPLOY` is `true`.
- That job uses the GitHub environment `cloudflare-workers-preview`. Create the environment and turn on **required reviewers** before setting the variable. The secrets do not exist yet, so the job is skipped.
- The upload step exits without uploading when `CLOUDFLARE_API_TOKEN` or `CLOUDFLARE_ACCOUNT_ID` is empty.
- The upload command is `wrangler versions upload`. `wrangler.jsonc` has no routes, so this does not attach `getqvi.com` or shift production traffic.

GitHub environment `cloudflare-workers-preview` secrets and variables (names only):

| Name | Kind |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Secret. Token permission: Account / Workers Scripts / Edit. |
| `CLOUDFLARE_ACCOUNT_ID` | Secret (or a var). Account id, not an API token. |
| `NEXT_PUBLIC_SUPABASE_URL` | Secret or var. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Secret. |
| `NEXT_PUBLIC_SITE_URL` | Variable. Use `https://beta.getqvi.com` for a beta build. |
| `CLOUDFLARE_PREVIEW_DEPLOY` | Repository or environment variable. Must be `true` to leave the skip. |

Set the runtime names (`RESEND_API_KEY`, `CONTACT_*`, `R2_*`, `QV1_OBJECT_KEY`) with `wrangler secret put` on the Worker after it exists. They are not needed to compile.

## Domain plan

Do this by hand after the Worker version looks right. Do not do it from CI.

1. Leave the apex `getqvi.com` grey-cloud CNAME aimed at Vercel.
2. On the `getqvi-web` Worker, add a **Custom Domain** for `beta.getqvi.com` (or a route `beta.getqvi.com/*` on the `getqvi.com` zone). The hostname must be proxied (orange cloud). A grey-cloud record does not run the Worker and does not set `request.cf.country`.
3. Exercise the beta host: home and `/ar`, `/api/geo`, sign-in, `/api/contact`, one ffmpeg tool, and `/qv1/download` (the download flag is currently paused in code).
4. Only after that, cut the apex over: replace the grey-cloud Vercel CNAME with an orange-cloud Worker custom domain or route for `getqvi.com` and `www` if `www` exists. Write down the previous CNAME target first.
5. Rebuild production with `NEXT_PUBLIC_SITE_URL=https://getqvi.com` before the apex serves the Worker.

`/downloads/evaluation/:path*` must keep redirecting to `https://dl.getqvi.com/qv1/evaluation/:path*`. That redirect is in `next.config.mjs` and does not depend on Vercel.

## DNS today and rollback

DNS for `getqvi.com` is on Cloudflare. The apex record that serves the site is a **grey-cloud (DNS only) CNAME to Vercel**. This change does not edit that record. Before any future edit, copy the current type, name, target, and TTL from the Cloudflare DNS panel.

Rollback, in order:

1. Remove the Worker route or custom domain for the hostname you switched (`beta.getqvi.com` or `getqvi.com`).
2. Restore the previous grey-cloud CNAME to Vercel if the apex was changed.
3. Confirm `https://getqvi.com` answers from Vercel.
4. Leave the Worker version in the Cloudflare dashboard; it does no harm while no route points at it.
5. Do not delete the Vercel project as part of rollback.

## Local check

```bash
npm ci
npm run build:worker
npx wrangler deploy --dry-run --outdir=/tmp/getqvi-worker-dry --minify
```

A local dry-run of this tree reported one binding, `env.ASSETS`, and a Worker upload of about 7038 KiB (gzip about 1929 KiB). That is under the 10 MiB paid script limit. esbuild prints a `baseStrategy` duplicate-key warning from a dependency chunk; the build still finishes.

`npm run preview` serves the Worker on your machine. It does not publish. `wrangler dev` simulates `request.cf.country` (often `US`), so `/api/geo` returns that country even if you send `x-vercel-ip-country`. Header fallback is covered by `lib/geo/request-country.test.ts`.

## Risks

- **CPU.** Budget Workers Paid before the first real request. Free-plan CPU is not enough for this SSR app.
- **Bundle.** The AWS SDK presigner is inside the Worker. `nodejs_compat` is what makes that signing path run. If a later build exceeds the Worker size limit, replace the presigner with a smaller SigV4 implementation that returns the same `https://<account>.r2.cloudflarestorage.com/...` URL. Do not switch the download to a Worker R2 binding without a separate change.
- **Build-time public env.** A preview built without `NEXT_PUBLIC_SITE_URL` advertises `https://getqvi.com` in metadata. Set the variable on the beta build.
- **Auth redirects.** Supabase will reject the beta callback until the redirect URLs include it.
- **Ads.** AdSense may not fill on a new hostname until the site is added.
- **Headers.** `next.config.mjs` COOP/COEP/CORS headers apply to Worker responses (HTML and API). Cloudflare static assets (`/_next/static`, files in `public/`) do not pass through that config. `public/_headers` marks `/_next/static/*` immutable. Document COEP still comes from the HTML response, which is what ffmpeg.wasm checks. Tool routes still send `Cross-Origin-Embedder-Policy: unsafe-none`.
- **Middleware.** Next.js 14 middleware is Edge and OpenNext runs it. Node.js middleware (a Next 15 option) is not used and is not supported by this adapter.
- **`global_fetch_strictly_public`.** Do not `fetch` a binding. Public HTTPS calls are fine.
